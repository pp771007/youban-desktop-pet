# 視覺與 UI 設計系統

目標水準：**商業產品等級**。判準不是「好不好看」這種感覺，而是下面第 1 節那張驗收表，每一條都要過。

## 1. 品質驗收表

| 項目 | 合格的樣子 |
|---|---|
| 清晰度 | 125%／150%／200% 縮放的螢幕上，邊緣、文字、圖示都銳利，沒有糊掉或鋸齒 |
| 一致性 | 所有間距落在 4px 格線上；圓角、陰影、顏色只用設計 token（設計變數）裡有的值 |
| 元件狀態 | 每個可以點的東西都有一般／滑過／按下／鍵盤焦點／停用五種樣子 |
| 動態 | 出現、消失、切換都有動畫，60fps，時間與曲線只用 token 裡定義的 |
| 深淺色 | 跟著 Windows 的深色／淺色模式切換，兩種都要好看，不是只有一種能看 |
| 對比 | 文字與背景對比至少 4.5:1 |
| 減少動態 | Windows 關掉動畫效果時，UI 動畫跟著縮短；桌寵本身的動作照常 |
| 對照稿 | 每個元件做完，截圖跟定稿的風格稿並排比對，看不出是兩回事才算完成 |

## 2. 哪些用 AI 出圖，哪些用程式畫

**原則：會放大縮小、會顯示文字、會有互動狀態的，一律用程式以向量畫。**
點陣圖放大就糊、文字燒死在圖裡改不了、按鈕的五種狀態 AI 也畫不一致 —— 這是「學生作品感」最主要的來源。

| 東西 | 誰做 | 說明 |
|---|---|---|
| 桌寵本身 | AI 出圖 | 規範見 `pet-pack-spec.md` |
| 風格稿（整體長相的定稿參考） | AI 出圖 | 決定配色、圓角、質感、氣氛；**是參考，不直接放進程式** |
| 空狀態插圖、首次啟動歡迎圖 | AI 出圖 | 大尺寸、純裝飾，點陣圖沒問題 |
| App 圖示的主視覺 | AI 出圖 → 我轉成多尺寸 | 16px、20px 這兩個尺寸要另外手調，AI 圖直接縮小會糊成一團 |
| 托盤圖示 | 程式畫（向量） | 16～32px 太小，必須逐像素對齊；從 App 圖示簡化而來 |
| 對話泡泡、頭上的框、右鍵選單、設定程式全部畫面 | 程式畫（向量） | 照風格稿實作 |
| 功能圖示（鈴鐺、齒輪、視窗…） | 專案自己畫的一套（SVG） | 24×24、線寬 2.25、圓頭圓角，主要形狀加一層 22% 透明度的同色填底（CSS 遮罩與 Direct2D 都只用 `currentColor`，所以一個顏色就畫得出兩階）；新增圖示照這個規格畫。檔案在 `crates/petsettings/ui/icons/`，頭上的框與設定程式共用同一份 |

## 3. 風格怎麼定

**全家族風格：B. 精緻平塗貼圖風** —— 乾淨俐落的深色輪廓線、賽璐璐兩階陰影、無外發光。
（四種畫風縮到 128px 放在深／淺／藍三種桌布上比較，B 的邊緣最乾淨，平塗色塊也最容易讓大量動作幀保持一致。）

1. **風格探索**：同一隻角色出 4 種畫風（提示詞見 `art-prompts.md` 第 0 步），你挑一種
2. **風格稿**：用挑中的畫風出 UI 風格稿（對話泡泡、確認框、選單、設定畫面）
3. **抽成 token**：我從風格稿量出顏色、圓角、陰影、字級，寫進 `design/tokens.json`
4. 之後所有新桌寵、新畫面都以這份為準 → 這就是「全家族同一個風格」的依據

**多隻桌寵與 UI 的關係**：UI 是全家族共用的「店面」，不跟著某一隻改長相；
但每個桌寵包可以帶一個「強調色」，對話泡泡的邊框、頭上的框的重點色會換成那隻的顏色，換桌寵時 UI 也跟著有感覺。

## 4. 設計 token（單一來源）

`design/tokens.json` 是唯一一份。建置時自動產生：

- 設定程式用的 CSS 變數
- 桌寵核心（Rust）用的常數

不會有「網頁那邊改了色、桌寵那邊沒改」的情況。

| 類別 | 內容 |
|---|---|
| 顏色 | 底色（三層深淺）、文字（主／次／停用）、強調色、語意色（成功／警告／錯誤）；深淺兩套 |
| 間距 | 4、8、12、16、24、32、48 |
| 圓角 | 小（按鈕）、中（區塊）、大（面板）、全圓 |
| 陰影 | 三個層級（貼地／浮起／彈出），深色模式另一套 |
| 字 | 字體、5 個字級、2 種粗細 |
| 動態 | 3 種時間（快／中／慢）、3 條曲線（進場／退場／彈跳） |

字體：預設 Windows 內建的「Microsoft JhengHei UI」—— 不用額外載入、跟系統一致；
風格稿若明顯需要更有個性的字，再評估內嵌一套（只載入用到的字）。

## 5. 元件清單

### 桌寵旁邊（核心程式畫）

| 元件 | 重點 |
|---|---|
| 對話泡泡 | 尾巴指向桌寵；靠近螢幕邊緣自動換邊；彈出時有回彈動畫 |
| 確認框 | 一眼看到：提醒內容（大字）＋時間＋「完成」「稍後」兩顆鈕；「稍後」展開 5／15／60 分鐘 |
| 錯過的提醒 | 醒來後一個框列出錯過幾則，可逐則完成或全部完成 |
| 提示框 | 跟確認框同樣子、沒有按鈕；右上角 ✕ 的外圈是倒數（從 12 點鐘順時針填滿），滿了自己收，滑鼠停在框上或人不在時停住 |
| 提示清單 | 好幾則傳話的提示框同時要跳時合成一個：版面同錯過的提醒、同一個來源排在一起，沒有按鈕，跟提示框一樣自己消失；超過的「還有 N 則」點了打開傳話紀錄 |
| 框疊起來 | 從桌寵頭頂往上長：要按的貼著桌寵，後面還有就露出最多兩層邊＋騎在上緣的「+N」；「+N」點開，在最前面那個上方列出其他的（每列一顆 ✓），點一列換它到最前面。會自己消失的放最上面。新東西只長在上面，最前面那個的按鈕位置不動；框剛換上來的半秒內按鈕不作用 |
| 專注倒數 | 飄在桌寵頭上的圓膠囊：專注用主題色＋番茄、休息用綠色＋茶杯；數字寬度固定，跳秒不伸縮；頭上有框或泡泡時讓開 |
| 右鍵選單 | 自己畫，不用 Windows 原生選單（原生的長相跟風格稿對不上）；有圖示＋文字；依功能分組、每組一個小標題，沒開的功能整組不出現；第二層（換桌寵）滑鼠移過去就在旁邊展開，每隻前面放牠的站姿小圖 |
| 托盤圖示 | 三種狀態：一般／有待處理的提醒／暫停中 |

### 設定程式

| 畫面 | 重點 |
|---|---|
| 主框架 | 左側導覽：桌寵、一般，底下「功能」一組（提醒、視窗歸位、專注），圖示＋文字；關著的功能用淡色 |
| 功能頁 | 標題旁邊就是這個功能的開關；關著時整頁只剩「已關閉」 |
| 提醒列表 | 下一次響的時間最醒目；暫停中的提醒用淡色，不用文字說明 |
| 提醒編輯 | 重複規則用選的不用打字；選完立刻預覽「接下來五次會在哪幾天響」，假日跳過的日子直接標出來 —— 用預覽代替說明文字 |
| 桌寵圖鑑 | 排成一格一格，每一格的桌寵都在動（只播待機動作）；目前使用中的有明顯標記；點一下就換 |
| 視窗歸位 | 目前記錄的視窗清單，「儲存」「恢復」兩顆主要按鈕 |
| 空狀態 | 每個清單沒東西時有插圖＋一顆「新增」按鈕，不是一片空白 |

## 6. 畫的技術

- **桌寵核心**：Direct2D ＋ DirectWrite（Windows 內建的繪圖與文字排版）畫進點陣圖，貼成逐像素透明的分層視窗。
  向量圖形、清晰文字、逐像素透明、每個螢幕各自的縮放比例都原生支援。
  向量圖示用 Direct2D 內建的 SVG 繪製。
- **設定程式**：網頁技術，吃同一份 token 產生的 CSS 變數。
