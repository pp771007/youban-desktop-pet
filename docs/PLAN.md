# 桌寵專案規劃

目標：一隻常駐 Windows 桌面的桌寵，**掛一個月記憶體不會越長越大、不用重開**；
基礎架構先做好，之後持續往上加功能；**多隻桌寵可切換**是核心功能。

第一版功能：提醒（含節假日跳過）、視窗歸位、桌寵切換。

---

## 1. 技術選型

| 候選 | 閒置記憶體 | 透明、可穿透點擊的視窗 | 呼叫 Win32 API（視窗歸位要用） | 長時間執行 |
|---|---|---|---|---|
| Electron | 自帶整套 Chromium，100MB 起跳 | 可以 | 要接原生模組 | GC，前端常見的慢性洩漏 |
| Tauri（WebView2） | 社群回報 70～160MB，分散在好幾個 `msedgewebview2.exe` | 可以 | Rust 端可以 | 畫面那半一樣是瀏覽器 |
| C# / WPF | 數十 MB 起跳 | WPF 透明視窗走軟體算圖 | P/Invoke 很順 | GC；外掛卸載（collectible ALC）出了名地漏 |
| **Rust 原生 Win32** | **實測（正式版）私有記憶體：睡覺時 6.4MB、有框跳出來時 11.8MB；CPU 單核 0.6%～2.6%** | 分層視窗原生支援逐像素透明，透明處滑鼠自動穿透 | `windows` crate 是微軟官方綁定 | **沒有 GC；資源綁在擁有者身上，擁有者消失就一定釋放** |

**結論：常駐的桌寵本體用 Rust 原生 Win32；設定畫面另外做成「用到才開」的程式。**

理由：

- 這個專案最重的需求是「長時間常駐、記憶體不漲」。Rust 的所有權機制讓「忘了釋放」在編譯期就過不了；
  計時器、事件訂閱、圖片都綁在某個擁有者上，擁有者被丟掉（drop）時一定一起收掉 —— 這正是外掛卸載要的保證。
- 桌寵與旁邊的 UI（對話泡泡、頭上的框、選單）用 Direct2D ＋ DirectWrite（Windows 內建的繪圖與文字排版）畫進點陣圖，
  再貼成分層視窗：向量 UI、清晰的中文字、逐像素透明、每個螢幕各自的縮放比例都原生支援，不需要瀏覽器。
  細節與為什麼不用 DirectComposition 見 `crates/petcore/src/render.rs` 檔頭。
- 視窗歸位、偵測螢幕重新連接、閒置偵測、開機自動啟動，全部是 Win32 API，Rust 直接呼叫。
- **設定畫面不常駐**：表單、清單、日曆這類畫面用網頁寫最快，所以設定程式用 Tauri；
  但它是**另一個程式**，按「設定」才啟動、關掉就結束 —— 行程結束時作業系統把它的記憶體全部收回，
  不靠任何人記得釋放。兩邊共用同一個 Rust crate 定義設定格式，不會兩份各改各的。

否決的路：整個 app 都用 Tauri（桌寵視窗常駐一個 WebView2，閒置就上百 MB，而且畫面那半回到 GC 的世界）；
Godot（遊戲引擎對單一小精靈太重，Win32 視窗操作還是要寫原生擴充）。

## 2. 架構

```
Youban.exe（crate petcore；Rust，常駐，可設定開機自動啟動）
├─ 桌寵視窗：逐像素透明的分層視窗、動畫狀態機、拖曳／掉落物理、向量 UI（泡泡／頭上的框／選單）
├─ 時鐘與排程器：全程式只有一個
├─ 模組（每個功能一個）：reminder / window-restore / pet-switch / …
├─ 托盤選單、log、記憶體看門狗
└─ 收設定程式的指令（WM_COPYDATA，JSON；指令名稱在 `petkit::ipc`），每秒檢查設定檔有沒有變

YoubanSettings.exe（crate petsettings；Tauri，用到才開，關掉即結束）
└─ 提醒編輯、桌寵切換、各模組設定

petpack.exe（命令列工具）
└─ 把 ChatGPT 出的圖整理成標準桌寵包（規範見 pet-pack-spec.md）

shared crate：設定與資料格式的型別，三支程式共用
```

### 開機自動啟動與系統管理員權限

開機自動啟動跟一般程式一樣，寫進目前使用者的「執行」登錄機碼（設定 →「一般」的開關）：不用系統管理員權限、
不跳 UAC，工作管理員的「啟動應用程式」裡也看得到、關得掉。

代價是一般權限的柚伴搬不動「以系統管理員身分執行」的視窗（例如工作管理員）—— Windows 不讓一般權限的程式動它們。
視窗歸位的結果卡會寫出有幾個搬不動；真的需要時自己以系統管理員身分開柚伴。

### 模組系統

- 每個功能是一個模組，實作 `Module` trait（`start` / 收事件 / `stop`）。
- 模組**只能**透過核心給的 `ModuleCtx` 註冊計時器、訂閱事件、載入資源；這些東西全部由 `ModuleCtx` 擁有。
  停用模組 = 丟掉它的 `ModuleCtx` → 底下所有東西一起釋放。模組自己偷開執行緒或計時器在結構上做不到。
- 模組 panic 只停掉那個模組並記 log，桌寵本體不倒。
- 模組可在執行中啟用／停用／改設定，不用重開。

### 時鐘

- 全程式一個時鐘、一個排程器，沒有各自的計時器。
- 桌寵動畫只在需要時重畫：被全螢幕程式蓋住或睡著時降到每秒 1～2 格，完全看不到時停止。
- 時鐘可以注入假的 —— 壓力測試可以快轉三十天，提醒的節假日邏輯也能直接測任何日期。
- 一律用「下一次觸發的絕對時間」排程，不用「再等 N 秒」：電腦睡眠醒來後重新算，不會漂移。

## 3. 記憶體控管

從結構擋，不靠事後抓漏：

1. **只載入目前這隻桌寵**，而且只解碼成目前顯示大小；常用動作常駐、少用的用到才載，超過預算丟最久沒播的。
   動畫張數不設上限，記憶體靠載入策略管（`pet-pack-spec.md` 第 5 節）。換桌寵時舊的整包丟掉。
2. **沒有無上限的集合**：每個佇列、快取、log 緩衝都有上限（用自訂的有界容器型別，不用裸 `Vec` 一直 push）。
3. **設定畫面在另一個行程**：最吃記憶體的瀏覽器只在打開設定時存在。
4. **看門狗**：每 10 分鐘記一筆私有記憶體用量（`GetProcessMemoryInfo`）到環形緩衝與 log；
   24 小時趨勢持續上升 → 桌寵冒泡提醒，並把當下狀態寫成診斷檔。
5. **壓力測試（每次改完都跑）**：假時鐘快轉 30 天，期間隨機拖曳、換桌寵 1000 次、模擬螢幕重新連接、
   觸發上千次提醒；暖機後記憶體曲線要是平的，不平就是紅燈。

## 4. 「不用重開」的範圍

| 情境 | 做法 |
|---|---|
| 改設定、增刪提醒 | 設定程式寫設定檔，核心一秒內讀到、立即生效 |
| 換桌寵、新增桌寵包 | 執行中切換；`pets` 資料夾放進新包會自動出現在清單 |
| 啟用／停用功能 | 模組執行中啟停 |
| 核心程式本身更新 | 下載 → 換檔 → 核心約 1 秒內重啟，桌寵回到原位、狀態接續（行程有換，但看不出來）|
| 不更新核心就加全新功能 | 外部外掛：另一個行程用同一套指令接上核心。**第一版不做** |

核心更新那一列老實講：換程式碼一定要換行程，能做到的是讓它無感。
所以所有狀態（視窗佈局、提醒的下一次觸發時間、桌寵位置）都要存到磁碟，不能只放記憶體。

## 5. 第一版功能

### 5.1 桌寵本體與切換

- 行為：在工作列上緣散步、坐下、眨眼；拖起來會晃、放開會掉下來落地；
  一段時間沒碰電腦（`GetLastInputInfo`）就睡著，一動滑鼠就醒；點一下會開心。
- 切換：托盤選單一鍵換、設定程式裡有縮圖清單；舊的消失、新的出現有過場效果。
- 每隻桌寵各自記住顯示大小（小／中／大）。
- 桌寵包壞掉（缺必要狀態、圖片不對）→ 拒絕載入並說明哪裡不對，不會讓程式倒。

### 5.2 提醒

**重複方式**：單次、每天、每週（選星期幾）、每月（第 N 天／最後一天／第 N 個星期幾）、
「工作日」、時段內每 N 分鐘（例如上班時間每小時喝水）。

**遇到假日怎麼辦**（每則提醒各自設定）：

- 照常提醒
- 跳過
- 順延到下一個工作日
- 提前到前一個工作日（繳費這類）

**什麼算假日**：

- 資料來源：人事行政總處「中華民國政府行政機關辦公日曆表」，政府開放資料
  [data.gov.tw 14718](https://data.gov.tw/dataset/14718)，每年 6～7 月公布隔年。
  格式已實測（116 年那份）：`西元日期,星期,是否放假,備註`，`0` = 上班、`2` = 放假；
  **補班的星期六會標 `0`**，所以「工作日」提醒在補班日照樣響。
- 每年自動抓一次存本機；**還沒公布的年份退回「只有週末是假日」，桌寵提醒一次**。
- 國定假日與補班列在提醒頁，每天一個開關（關掉 = 照週末規則）。
- 手動覆寫：颱風假、請假這類「額外上班／放假日」→ 這天放假／上班。

**提醒的樣子**：桌寵切到「提醒」動作＋對話框；點對話框 → 完成／稍後 5、15、60 分鐘。
可另外勾選要不要同時發 Windows 通知。

**電腦關機或睡眠時錯過的**：醒來後列出錯過的提醒，不會一次全部轟出來。

### 5.3 視窗歸位

照搬 session-window-manager 已驗證過的行為：

- 螢幕重新連接 → 等 3 秒穩定 → 螢幕配置與存檔時相同才自動恢復
- 新開的視窗一分鐘內自動記錄位置，記下時桌寵說一聲（設定裡可關）；手動「儲存佈局」「恢復佈局」放在桌寵右鍵選單
- 排除系統程式（終端機除外）、排除桌寵自己的視窗
- 設定裡點一個記下的視窗，直接打 X、Y、寬、高，套用時馬上搬過去

跟原版不同的一點：**佈局存到磁碟**。原版只放記憶體，而桌寵核心更新會重啟一次，放記憶體會在更新時遺失。

## 6. 分段

| 段 | 內容 | 完成的判準 |
|---|---|---|
| 0 | 選型實測 | 桌寵視窗跑一段 60fps 動畫 24 小時，記一條記憶體曲線；Tauri 設定程式開關 50 次，核心記憶體回到原點 |
| 0' | 定風格（你那邊，與 0、1 平行） | 照 `art-prompts.md` 出風格探索 → 角色設定稿 → UI 風格稿；我抽成 `design/tokens.json` |
| 1 | 核心骨架 | 桌寵視窗、動畫狀態機、拖曳掉落、托盤、模組系統、設定存檔、log、看門狗、壓力測試框架 |
| 2 | 桌寵包＋切換＋桌寵旁 UI | `petpack` 匯入工具、執行中切換、對話泡泡／確認框／右鍵選單；圖還沒到就先用暫代桌寵 |
| 3 | 提醒 | 含日曆抓取、四種假日處理、錯過補報 |
| 4 | 視窗歸位 | 從 session-window-manager 移植，加存檔 |
| 5 | 設定程式 | 提醒編輯、桌寵清單、各模組設定 |
| 6 | 自動更新 | 換檔＋無感重啟＋狀態接續 |

每一段的 UI 都要過 `design-system.md` 第 1 節的品質驗收表才算完成。
